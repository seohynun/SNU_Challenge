## 1. 전체적인 방법론 및 모델 구조 (Overview & Architecture)

### 1.1 문제 정의와 본질적 어려움

뒤섞인 4개의 비디오 프레임과 텍스트 캡션이 주어졌을 때, 각 프레임의 실제 시간적 순서 `[n, n, n, n]`을 복원하는 문제다. 어려운 이유는 네 가지다.

1. **평가 지표의 엄격성**: Exact Match Accuracy로 부분 점수가 없다. 24개 순열 중 정확히 하나를 맞혀야 하며, 무작위 기준선은 1/24 ≈ **4.2%**에 불과하다.
2. **Zero-shot의 완전한 무력함**: 후보 VLM 5종(Qwen2-VL-2B, Qwen2.5-VL-3B/7B, Qwen3-VL-2B/4B)을 holdout_300에 평가한 결과 acc_shuffled가 **0.8~4.4%로 무작위 기준선과 동급**이었다. 사전학습된 VLM이 "이미 할 줄 아는 것"이 아닌, 출발선 0의 문제다.
3. **VLM의 구조적 위치 편향(Positional Bias)**: 멀티 이미지 VLM은 "먼저 제시된 프레임 = 시간상 먼저"라는 강한 사전 편향을 지닌다. 이미지 제시 순서는 무작위(정보량 0)임에도 모델 예측이 제시 위치에 끌려가며, identity(`[1,2,3,4]`) 지름길 오답의 구조적 원인이 된다.
4. **문장의 시간적 모호성 편차**: 시간 표지 없는 문장은 정확도가 40.5%p 폭락하고 카메라 표현 유무가 +26.9%p를 가르는 등, 문장의 시간적 명확성(Temporal Clarity)에 따라 난이도가 극단적으로 갈린다.

### 1.2 실험 공통 규약 및 용어 정의

| 용어 | 정의 |
| --- | --- |
| **holdout_300** | train.csv 9,535건에서 분리한 고정 평가셋 300건 — 셔플 샘플 252건 + 비셔플 샘플 48건. 모든 파인튜닝에서 자동 제외 |
| **acc_shuffled** | holdout 중 셔플 252건만의 정확도 — 핵심 판정 지표. 비셔플 포함 총점은 identity 남발만으로 올라가는 착시가 있어 판정에 사용하지 않는다 |

### 1.3 End-to-End 파이프라인 개요

최종 파이프라인은 **보조 모델의 역할을 학습 데이터 설계로 한정하고 추론 파이프라인에서는 완전히 배제하는 역할 분리 원칙** 위에 설계되었다. 전처리 보조 자산(Gemma4 문장 라벨, CLIP 장면 분할, MSE 미세움직임 지표)은 데이터 설계(증강 배수·셔플 순열 결정)에만 사용하고 추론에는 일절 탑재하지 않는다. 최종 추론은 Qwen3-VL-8B + LoRA 어댑터 1개의 단일 모델로 수행된다.

```
[학습 시점 (오프라인)] — 문장 축과 이미지 축은 별개 경로로 진행

  train.csv (9,535 문장)                  train/ (프레임 이미지)
        │                                       │
  [문장 전처리]                            [이미지 전처리]
  Gemma4-12b 로컬 라벨링                   CLIP(ViT-B/32) 유사쌍·씬컷 검출 (임계 0.20)
  (5필드: 주체/사건/카메라/시청자/시간표지)     Adjacent MSE 미세움직임 판정 (임계 800)
        │                                       │
        ▼                                       ▼
  [문장 4유형 분류]                        [하드 셔플 순열 선별 (hard_perm)]
  비카메라 사건수(≤2/≥3) × 카메라표지(O/X)   CLIP 유사쌍 역전 ×10 가중 채점
        │                                       │
        ▼                                       │
  [차등 증강 가중치 CSV: sparse_camX ×4, 기타 ×2]   │
        └──────────────┬────────────────────────┘
                       ▼
  [재셔플 증강 사본 23,814개 생성]
                       ▼
  [QLoRA 파인튜닝: Qwen3-VL-8B NF4 4bit, r=16, q/k/v/o]
  (Kaggle T4×2, 1,488 step 완주)

[추론 시점 (RTX 3090)] — 보조 모델 미탑재

  test 샘플 (문장 + 프레임 4장)
                       ▼
  [우도 K=4 순열 TTA]
   ① 이미지 제시 배치를 4가지 순환이동(라틴방진)으로 구성
   ② 각 배치에서 24개 순열 후보 전부를 teacher-forcing 로그우도로 채점
   ③ 후보별 4개 배치 점수 합산 → argmax 제출

```

## 2. 제안한 아이디어의 동기와 핵심 기여 (Motivation & Key Contributions)

### 2.1 베이스라인의 한계 분석

제공된 베이스라인(Qwen2-VL-2B zero-shot + greedy 생성 + 출력 파싱)은 세 겹의 한계를 지닌다.

1. **능력의 한계**: zero-shot acc_shuffled 0.8~4.4% — 순서 복원 능력 자체가 없다.
2. **디코딩 방식의 한계**: 답 공간이 순열 24개로 닫혀 있음에도 greedy 생성은 이를 주관식으로 푼다. 첫 토큰 갈림길에서 결합 확률이 더 높은 순열을 놓치는 근시안(myopia)이 존재하고, 출력 형식이 깨지면 파싱 실패로 자동 오답 처리된다.
3. **편향의 한계**: 위치 편향에 의한 identity 지름길 — 오답 해부 결과 `[1,2,3,4]` 그대로 답하는 것이 주요 오답 모드였다.

### 2.2 핵심 아이디어

세 한계에 각각 대응하는 레버를 설계했다.

- 문장 난이도 기반 Data-Centric 차등 증강으로 약점 유형을 집중 학습
- 답변 생성에서 답변 채점으로 추론 방식을 재설계하여 24지선다 우도 평가 문제로 전환
- 이미지 배치를 라틴방진 4회전으로 바꿔가며 채점을 합산해 위치 편향을 구조적으로 상쇄

### 2.3 본 연구의 3대 기여

**기여 1 — 언어학 이론 기반 문장 4유형화와 차등 증강 (Data-Centric Augmentation).**
Vendler 동사 상 이론(종결성 있는 사건만 시간 정렬의 앵커), TimeML/TempEval-3(시간 표지 유무가 1차 판별선), SDRT 담화 구조 이론(카메라·편집 지시어의 서사 분리)을 배경으로, 로컬 Gemma4-12b로 9,535문장을 5필드(주체·사건·카메라·시청자·시간표지)로 전량 라벨링했다(파싱 성공률 100%, 이벤트 정밀도 94.2%). **비카메라 사건 수(≤2/≥3) × 카메라 표지(O/X)의 4유형**은 holdout 실측에서 21.6%~73.8%의 뚜렷한 성능 계단을 보여 확정되었다. 최약점 유형 `sparse_camX`에 증강 배수 ×4를 부여하는 차등 증강 CSV가 이 인사이트의 구현체이며, 라벨은 증강 배수 결정에만 사용하고 모델 입력에는 주입하지 않는다.

**기여 2 — 생성에서 채점으로: 우도 K=4 순열 TTA (추론 패러다임 전환).**
24개 순열 후보 전부를 teacher-forcing 로그우도로 채점하고, 이미지 제시 배치를 순환이동 4가지(라틴방진: 모든 이미지가 모든 슬롯을 정확히 1회 방문)로 바꿔 점수를 후보별 합산한다. 학습이 전혀 필요 없는 순수 추론 레버로, **holdout +4.76%p, Private +4.1%p**의 프로젝트 단일 최대 개선을 달성했다.

**기여 3 — 자원 제약 하 단계적 스케일링과 보조 모델의 학습 단계 한정 활용.**
2B 레시피 확립 → 4B 검증(+7.3%p) → 8B 완성의 3단계 스케일링을 NF4 4bit QLoRA로 수행하여, 8GB 노트북 GPU에서 4B 학습(peak 3.8~6.2GB)과 RTX 3090(24GB)에서 8B 구동을 실현했다. 전처리 보조 모델(Gemma4/CLIP/OWL-ViT)은 추론 파이프라인에서 완전히 배제하여 단일 모델 규정을 준수하면서 그 인사이트를 LoRA 가중치에 내재화했다.

## 3. 학습 및 추론 과정, 주요 기법 (Training & Inference / Proposed Methods)

### 3.1 데이터 전처리 (1): 문장 성분 정밀 라벨링 — Gemma4 로컬 인프라

정규식 기반 1:1 매칭은 상적 변화(Aspectual Coercion) 등 문맥적 상 변이를 처리하지 못한다. **로컬 Gemma4-12b(WSL Ollama)**로 전체 9,535건을 전량 라벨링했다.

- **추출 스키마**: JSON 5필드 (`subjects`, `events`, `camera_language`, `viewer_language`, `temporal_markers`)
- **Ops 최적화**: `think: false` 강제, Flash Attention 재기동으로 27.7초/문장 → **8.9초/문장 (3.1배)**, 300건 단위 JSONL 롤오버로 중단 시 자동 이어받기. 총 ~7.3시간 완료.
- **품질 검증**: 파싱 성공률 100%, 카메라 라벨 정규식 대조 92.1%, 수작업 GT 100건 이벤트 Precision **94.2%** / Recall 91.8%.
- **모델 선정**: Gemma4-e4b는 사건 과소 분할("misses a buoy" 누락)로 기각, 12b 채택.

**외부 API 비용: 0원.** 전 전처리가 100% 로컬 인프라에서 수행되었다.

### 3.2 데이터 전처리 (2): 이미지 물리·장면 분석 — CLIP 씬컷과 MSE 미세움직임

**[추후 데이터 넣기: 이미지 전처리 파이프라인 다이어그램 — 이병철 파트 그림 삽입]**

- **CLIP(ViT-B/32) 씬컷 검출**: 픽셀 MSE의 whip pan 오판·단색 배경 오류를 극복하기 위해 ResNet-50/DINOv2/CLIP 벤치마킹 끝에 CLIP 채택. 코사인 거리 **0.20**을 위탐지율 4.8% 미만의 통계적 최적 임계값으로 확정. 6쌍 중 5개 이상이 유사쌍이면 전환 0회로 판정(Loose 기준): 0회 27.7% / 1회 39.5% / 2회 21.4% / 3회 11.4%.
- **탐색 공간 축소의 수학적 근거**: Union-Find 기반 장면 군집화로 1회 전환(`[{0,1},{2,3}]`) 감지 시 유효 순열이 24 → 4개로 **83.3% 축소** — 단, 최종 추론에는 적용하지 않았다(분석 근거로만 사용, §6.2-4의 후속 과제).
- **Adjacent MSE 미세움직임 판정**: 전환 0회 정적 비디오(27.7%)는 32×32 grayscale 평균 MSE < 800이면 Fine-grained(고난도)로 분류.

이미지 피처의 최종 사용처: **CLIP 유사쌍 → 하드 셔플 순열 선별**(§3.4), **scene_cuts → v10 힌트 실험**(§3.5). 문장 4유형 분류(§3.3)에는 이미지 피처가 사용되지 않는다.

### 3.3 문장 4유형 정의와 holdout 실측 확정

비카메라 사건 수(n_events_noncam ≤2 / ≥3)와 카메라 표지 유무(camO/X)의 두 축으로 유형화했다. 카메라·편집 지시어를 사건 수 계산에서 제외하는 것이 핵심 설계 — 미제외 시 카메라 표현 문장의 평균 사건 수가 4.10 → 3.00개로 과대평가되어 저밀도 문장이 중밀도로 위장된다.

| 문장 유형 | Holdout 정확도 | Train 분포 | 전처리 전략 |
| --- | --- | --- | --- |
| **sparse_camX** | **21.6%** (n=74) | 2,755 (29%) | 최약점 → 차등 증강 ×4 |
| sparse_camO | 48.7% (n=39) | 1,114 (12%) | ×2 |
| dense_camX | 52.7% (n=74) | 3,084 (32%) | ×2 |
| dense_camO | 73.8% (n=65) | 2,582 (27%) | ×2 (최명확 앵커) |

세부 인자 절벽: 시간 표지 0개 17.2% vs 있음 57.7% (**−40.5%p**), 카메라 표현 유무 +26.9%p.

### 3.4 재셔플 증강과 차등 배수 — identity 편향의 학습적 처방

재셔플 증강은 "제시 순서 그대로 답하기"(identity 지름길)를 학습 단계에서 차단하는 핵심 장치다. ×2가 ×1보다 +6.4%p 우수했고(exp07 48.41% vs exp06 42.06%), §3.3의 차등 배수(sparse_camX ×4)를 결합했다.

CLIP 유사쌍의 시간 순서를 의도적으로 역전하는 **하드 네거티브 셔플(hard shuffle)**은 주 오답 모드인 쌍교환(pair-swap)을 겨냥한 설계로, 무작위 후보 16개를 "유사쌍 시간 역전 쌍 수 ×10 + 프레임 위치 이탈량 합"으로 채점해 최고점 순열을 선별한다(`hard_perm()`). 4B greedy 통제 실험(exp20)에서 holdout +0.4%p / **Public −1.1%p 역효과**로 기각 판정되었다. 단, 최종 8B는 마감 일정상 이 레시피로 977 step까지 학습된 체크포인트를 이어서 완주시키는 선택을 했으며, 결과적으로 TTA와 완주 효과가 셔플 방식의 불리를 상회하며 1위에 도달했다 — 4B greedy 조건의 기각 판정이 8B+우도 조건으로 그대로 이전되지 않은 사례다.

### 3.5 프롬프트 엔지니어링 — v5_reorder (문장 후치)

프롬프트 구조 실험 15종에서 역할 부여·스토리텔링 등은 전부 노이즈였고, **문장(캡션)의 위치 이동만이 유일하게 양성**이었다. 캡션을 지시문 뒤, 정답 출력 직전에 배치하는 v5_reorder는 추론 스크리닝 → 미니 스크리닝 → 풀 학습(Public 0.775 > 0.766)의 3단계 검증 전부에서 양성이었던 유일한 후보다.

```
Look at the 4 images above labeled Image 1 to Image 4. Determine the correct
chronological order of these images to match the sentence below.
Sentence: "{sentence}"                        ← 문장이 맨 뒤 (답 직전)
Provide the answer ONLY as a Python list of integers. Example: [1, 2, 3, 4]
```

기준 프롬프트 v1_list와의 차이는 문장 배치뿐이다 — v1_list는 첫 줄에 문장이 오고, v5_reorder는 같은 문장을 지시문 뒤로 옮겼다. 자기회귀 생성에서 문장이 답 직전에 오면 모델이 이미지를 본 뒤 문장을 "신선한 상태"로 참조하며 매핑한다.

**v10**은 v5_reorder 위에 CLIP scene_cuts 수치 힌트를 학습 프롬프트에 부가한 실험본이다. **[추후 데이터 넣기: v10 scene_cuts 힌트 블록 원문과 run config]**

**CoT 지도학습은 4회 연속 실패로 영구 기각**되었다: 풀 학습 CoT(exp12, −4.4%p)와 미니 스크리닝 3종 — gemma 사건 타깃 CoT 3.17%, 구조요약 CoT 3.17%(identity 응답 91.7% 폭주), gemma 텍스트 힌트 9.92%(기준선 15.5%). 공통 붕괴 모드는 이미지 근거 없이 identity 응답(81~92%)으로 쏠리는 것이었다.

### 3.7 추론 기법 — 우도 K=4 순열 TTA (핵심 제안)

**(a) 생성 → 채점 전환 (Likelihood Scoring).** 정답 공간은 순열 24개로 닫혀 있다. 프롬프트 $x$(문장 + 이미지 4장)가 주어졌을 때, 각 후보 순열 $a \in S_4$에 대해 답 문자열 $y(a) =$ `"[a1, a2, a3, a4]"`를 토큰열 $(t_1, \dots, t_L)$로 분해하여 조건부 로그우도를 teacher forcing으로 계산한다:

$$
s(a) \;=\; \sum_{k=1}^{L} \log P_\theta\big(t_k \,\big|\, x,\; t_1, \dots, t_{k-1}\big)
$$

greedy 생성이 토큰 단위 국소 argmax의 연쇄인 반면, $s(a)$는 후보 문자열 전체의 **결합 확률**을 비교하므로 (i) 파싱 실패 오답이 원천 소멸하고, (ii) 첫-토큰 근시안이 교정된다. 24개 후보는 모두 `[n, n, n, n]` 꼴로 토큰 구조·길이가 동일하므로 길이 보정이 불필요하다. 프리픽스 forward 1회의 KV 캐시를 24개 후보가 공유하므로 후보당 추가 비용은 짧은 답 토큰열 1회 forward에 불과하다.

**(b) K=4 순환 배치 TTA (라틴방진 합산).** 이미지 제시 배치 $\pi$를 순환이동 4가지 $\Pi = \{(1,2,3,4),\,(2,3,4,1),\,(3,4,1,2),\,(4,1,2,3)\}$로 바꿔가며 (a)의 채점을 반복한다. 이 4개 배치는 모든 이미지가 4개 제시 슬롯을 정확히 1회씩 방문하는 최소 균형 집합(라틴방진)이다. 배치 $\pi$ 하에서 원본 좌표의 후보 $a$를 채점하는 문자열은

$$
y_\pi(a) \;=\; \big[\,a_{\pi(1)},\; a_{\pi(2)},\; a_{\pi(3)},\; a_{\pi(4)}\,\big]
$$

로 재매핑된다. 최종 점수와 제출은

$$
\mathrm{Score}(a) \;=\; \sum_{\pi \in \Pi} s_\pi(a), \qquad \hat{a} \;=\; \arg\max_{a \in S_4} \mathrm{Score}(a)
$$

이다. 다수결이 아닌 우도 합산을 쓰는 이유: 위치 편향이 주는 가짜 점수는 배치마다 서로 다른 후보에 1회분씩 흩어지지만, 진짜 시각 근거는 항상 동일한 후보 $a$에 4회분 누적된다. 합산 구조에서 편향은 분산되고 근거는 축적된다.

**(c) 제출 형식 역변환과 좌표 버그 사례.** 좌표 변환이 겹겹이 존재하는 구조상, 이미 제출 형식인 argmax 후보에 역순열 변환을 한 번 더 적용한 **중복 역변환 버그** 제출본은 Public 0.44677(무작위 수준 이하)로 추락했고, 한 단계 원복만으로 0.88830으로 회복되었다. 좌표 규약 단위 테스트가 본 기법의 필수 전제임을 실증한 사례다.

**(d) 구현 세부 (`INFER_ONLY_K4.py`).** 프리픽스 KV 캐시를 배치 축으로 복제(`batch_repeat_interleave`)하여 24개 후보를 청크 단위(기본 6개, CUDA OOM 시 자동 반감 재시도)로 병렬 채점한다. 답 토큰열에는 종료 토큰(`<|im_end|>`)까지 포함해 형식 편향을 차단한다. M-RoPE의 position id 오프셋(`rope_deltas`)을 프리픽스에서 이어받아 답 토큰 위치를 정렬한다. argmax 후보는 추가 변환 없이 그대로 제출 — (c)의 버그 재발을 코드 레벨에서 고정한 지점이다. prior 차감 옵션은 holdout 실측에서 shuffled 무영향·identity 하락으로 확인되어 미사용했다.

**(e) 실측 효과.** 로컬 4B(exp17)에서 holdout acc_shuffled **[추후 데이터 넣기: 51.98/52.38 확인]** → **57.14% (+4.76%p)**. 8B 977 step에서 Greedy Private 0.81300 → TTA Private 0.85365 (**+4.1%p**). 1488 완주 + TTA 최종본이 Private **0.86991 (1위)**. TTA 적용 전후 acc_identity 변화는 **[추후 데이터 넣기]**로, 우도 합산이 비셔플 샘플을 훼손하지 않음을 함께 보인다.

**(f) 규정 적합성.** 학습 없음, 입력은 대회 제공 문장+이미지, TTA는 §4.3 명시 허용 조항에 해당, 외부 모델·피처 주입 없음.

### 3.8 전처리 자산의 최종 연동 방식 — 추론 배제, 학습 내재화

추론 코드에 보조 모델을 탑재하는 안은 (i) 8B가 추론 GPU 메모리 대부분을 점유하는 조건의 CUDA OOM 리스크, (ii) 819문항 × 프레임별 검출 연산의 24시간 초과 리스크, (iii) 물리 정합률 ~60%의 하드 필터가 나머지 40%에서 정답을 역전시키는 취약성으로 기각되었다. CLIP 씬 분할·MSE 미세움직임 정보는 학습 데이터의 증강 배수 가중치와 하드 네거티브 선별 가중치로 연동되어 LoRA 가중치에 내재화되었고, 추론 시에는 8B 단독 연산만 남는다.

### 4.4 977 vs 1488 완주 학습의 데이터 커버리지 인과 분석

977→1488 완주의 Private +1.63%p가 단순히 "더 오래 학습해서"가 아니라 **어떤 데이터가 채워져서**인지를 두 독립 증거로 규명했다. 본 절 분석은 예선 마감(7/24) 이후 사후(post-hoc) 진단으로, 어떠한 학습·설계 결정에도 사용되지 않았다(규정 §3.4 데이터 누수 금지 준수).

**증거 1 — Train 커버리지 감사.** 총 증강 사본 23,814개 중 977 step까지 8,182개(34.4%)가 미학습이었다. 유형별 분해(모수는 학습 유니버스 9,235건 기준):

| 유형 | 배수 | 총 사본 | 미학습 사본 (8,182 중) | 완전미학습 ID (837 중) | Test 변경률 | z-score |
| --- | --- | --- | --- | --- | --- | --- |
| dense_camO | ×2 | 5,000 | 1,754 (21.4%) | 317 (37.9%) | 12.2% | −3.39 |
| dense_camX | ×2 | 5,990 | 2,067 (25.3%) | 368 (44.0%) | 20.9% | −0.37 |
| sparse_camO | ×2 | 2,136 | 702 (8.6%) | 116 (13.9%) | 13.0% | −1.84 |
| **sparse_camX** | **×4** | **10,688** | **3,659 (44.7%)** | 36 (4.3%) | **52.0%** | **+7.38** |

상반된 두 패턴이 드러난다. ×4 증강 sparse_camX는 완전미학습 확률 (0.344)⁴ ≈ 1.4%로 ID를 36개(4.3%)만 유실했지만, 사본 절대량이 많아 완주 구간 미학습 사본의 44.7%를 단일 유형이 차지했다. 반면 ×2 증강 dense 계열은 (0.344)² ≈ 11.8%가 뚫려 완전미학습 837개의 81.8%가 dense 계열에 집중되었다.

**증거 2 — Test 예측 대조.** 977본과 1488본은 819건 중 177건(21.6%)에서 예측이 갈렸다. 효과가 일반적 수렴이었다면 변경률이 유형과 무관하게 균등(≈21.6%)해야 한다. 실측은 **sparse_camX만 52.0%(z = +7.38)**으로 압도적으로 이탈했으며, 이는 증거 1의 "완주 구간 집중 주입" 유형과 정확히 일치한다. dense_camX의 88건은 절대량으로 최다급이지만 변경률 20.9%로 전체 평균과 통계적으로 동일(z = −0.37)하다.

**증거 3 — 성분 축 매칭.** ev_4+(사건 4개 이상) 문장이 Train 유실 점유율 1위(43.6%)이면서 동시에 Test 예측 변경 절대량 1위(77건)로, "무엇이 비었나"와 "무엇이 바뀌었나"가 1:1로 수평 매칭된다. mark_0(시간표지 없음)의 변경률 51.0%는 자체 미학습이 아니라 Test mark_0 96건 중 76%가 sparse_camX 소속인 결합 교란(confounding)으로 판정되었다. **[추후 데이터 넣기: mark_0∩sparse_camX 비율 — 54.2%/76% 상충, CSV로 확정]**

**결론.** 완주의 +1.63%p는 학습량 일반의 효과가 아니라 **sparse_camX 사본 대량 주입 + ev_4+ 고밀도 문장 커버리지 보충** 효과로 귀속된다.

**처방.** ① ×2에 방치된 dense 계열에 ×3~4 상향 — 배수는 약점 강조 장치이자 조기 중단에 대한 커버리지 보험이다(×4를 받은 sparse_camX가 완전미학습 1.4%로 방어된 것이 그 증거). ② `[dense/sparse]×[camO/X]×[mark_0/1+]` 8유형 멀티티어 증강 체계 도입, 최고 난이도 니치(dense_camX_mark0)에 최우선 배수 부여. ③ 에폭 내 사본 균등 배치를 보장하는 Stratified DataLoader 도입. **[추후 데이터 넣기: 커버리지 통계 원본 CSV 대조 — submission_diff_by_type.csv, all_untrained_items_raw.csv]**

### 4.5 Error Analysis — 실패에서 얻은 인사이트

**(a) Identity 지름길.** 주요 오답 모드 1: `[1,2,3,4]` 그대로 응답. 재셔플 증강(학습 쪽)과 우도 K=4 TTA(추론 쪽)로 이중 차단했다. CoT SFT 4연패도 본질은 identity 폭주(81~92%)로의 붕괴였다.

**(b) 쌍교환(pair-swap).** 주요 오답 모드 2: 비슷한 두 프레임의 선후 혼동. 파라미터 체급 문제로 진단되어 8B 스케일업의 근거가 되었다(미니 2B→4B +13.5%p가 방증). 이를 직접 겨냥한 하드 셔플은 holdout +0.4%p / Public −1.1%p 역전으로 기각 — holdout과 리더보드 분포 불일치 가능성을 시사하는 반례다.

**(c) 힌트 주입 계열의 전멸.** Gemma 문장 성분 힌트, OWL-ViT 객체 궤적, 물리 정합 실시간 필터 모두 기각. 공통 원인: 모델이 스스로 계산 가능한 정보의 명시적 주입은 무익하고, 정합률 60%짜리 불완전 힌트 강제는 나머지 40%에서 정답을 역전시킨다. 보조 자산의 올바른 자리는 데이터 선별과 증강 가중치였다.

**(d) 구현 버그.** 우도 TTA의 중복 역변환 버그 제출(Public 0.447) → 원복 후 0.888 회복. 채점·역변환 경로에는 단위 테스트가 필수 전제임을 실증했다.

## 5. 자원 및 비용 효율성 (Efficiency & Optimization)

### 5.1 하드웨어 제약과 대응 전략

평가 환경은 RTX 3090(24GB) 1대, 인터넷 차단, 전체 모델 80GB 이하, 819샘플 24시간 이내(샘플당 ≈105초)다. 개발 주력은 RTX 5060 Laptop 8GB이었으며 다음으로 극복했다.

- **NF4 4bit QLoRA**: 4B 학습 peak 3.8~6.2GB — 8GB 노트북에서 4B 파인튜닝을 가능하게 한 핵심 경량화.
- **학습 아웃소싱**: 로컬 불가한 8B는 Kaggle T4×2(16GB×2, 무료)에서 학습, 추론만 3090 대응.
- **오프라인 패키징**: `HF_HUB_OFFLINE=1` 리허설, 가중치 로컬 이식으로 차단 환경 대응.

### 5.2 체급별 스케일링·효율 실측표

| 체급 | 정밀도 | 학습 VRAM Peak | 추론 속도 (greedy) | acc_shuffled | Public | Private | 평가 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Qwen3-VL-2B (exp16) | bf16 | 6.4 GB | 0.85초/샘플 | 48.02% | 0.784 | 0.760 | 2B 체급 한계 |
| Qwen3-VL-4B (exp17) | 4bit | 3.8~6.2 GB | 1.14초 | 51.98% | 0.857 | 0.825 | Public 대약진 |
| Qwen3-VL-4B (v10) | 4bit | 3.8~6.2 GB | 1.22초 | 51.50% | 0.855 | **0.854** | 자원 효율 최적점 |
| **Qwen3-VL-8B (완주)** | 4bit | 11.2 GB | 2.16초 | **54.67%** [추후] | **0.883** | **0.870** | 대회 1위 |

**자원 효율 분석 — 4B의 효율은 양자화가 아닌 레시피 최적화의 산물이다.** 4B v10은 8B 대비 파라미터·메모리 절반, VRAM 3.8GB에서 구동 가능하면서 최종 1위 모델 성능의 98%(Private 0.854 vs 0.870)에 도달했다. 이 효율이 단순 경량화가 아님은 두 직접 비교가 보여준다.

- **greedy 조건**: 레시피 최적화된 4B v10(Private 0.854)이 8B 977 step greedy(0.813)를 **+4.1%p 압도**
- **동률 비교**: 4B v10 greedy(0.85365) = 8B 977 + 우도 K=4 TTA(0.85365) — 잘 설계된 4B는 최강 추론 레버를 얹은 미완성 8B와 맞먹는다

단순 체급 확대보다 **EDA 기반 레시피 최적화가 더 결정적**이라는 것이 본 프로젝트의 핵심 설계 인사이트다. 한편 v10은 추론 시 CLIP(ViT-B/32) 힌트 생성을 수행하는 구성이다 — 로컬·경량 모델이라 자원 부담은 미미하지만, "보조 모델 추론 미탑재" 원칙(§1.3)은 최종 8B 시스템에 대한 서술이며 v10에는 적용되지 않는다.

### 5.3 추론 시간 예산 검증

우도 K=4 TTA의 계산 비용은 두 축으로 나뉜다. **후보 24개 축은 프리픽스 KV 캐시 공유로 사실상 무료**이고, **배치 4개 축이 비용의 본체**다 — 배치마다 이미지 4장 인코딩을 새로 계산해야 하므로 이론 비용은 greedy의 약 4배다. 실측은 RTX 5060 8GB의 4B+K4 기준 약 31초/샘플(greedy 1.14초의 약 27배)로, KV 캐시 복제·청크 분할·저메모리 오버헤드에서 격차가 발생한다. Kaggle T4×2의 8B+K4는 약 1~2시간으로 완주했으며(예산 24시간의 1/10 이내), 채점 환경 RTX 3090은 개발 환경보다 상위 사양이다. 추론 시 보조 모델을 일절 로드하지 않는 단일 모델 구성이 OOM과 지연 리스크를 원천 제거한다.

### 5.4 구축 비용

- **외부 상용 API 비용: 총 0원** (한도 3만 원). Gemma4-12b 라벨링(~7.3시간), CLIP 피처 추출, MSE 분석 전부 로컬 수행.
- **학습 연산량**: 2B/4B는 소비자급 노트북(8GB), 8B는 무료 Kaggle T4×2. 유료 클라우드 학습 비용 0원. **[추후 데이터 넣기: 8B 완주 총 학습 시간]**
- **전처리 자동화**: 라벨 → 4유형 분류(`structure_features.py`) → 증강 가중치 CSV(`aug_weights_exp16.csv`) → `train.py --aug-weights`로 100% CLI 자동 매핑.

## 6. 결론 및 한계점 (Conclusion & Limitations)

### 6.1 결론

zero-shot 0.8%에서 출발해 Public 최고 0.88830 / Private 최고 0.86991(대회 1위)에 도달하는 전 과정을 통제 실험과 실측 근거로 구축했다. 성능의 원천은 세 레버다: (1) 언어학 이론과 로컬 LLM 라벨링으로 약점 유형에 학습을 집중시킨 **Data-Centric 차등 증강**, (2) v5_reorder·증강 배수·체급 스케일링의 **레시피 최적화**(greedy 조건에서 레시피 최적화된 4B가 미완주 8B를 이긴다), (3) 닫힌 답 공간을 활용해 생성을 전수 채점으로 바꾸고 라틴방진 배치 합산으로 위치 편향을 상쇄한 **우도 K=4 순열 TTA** — 학습 비용 0으로 Private +4.1%p.

방법론의 원칙 두 가지: **판정은 실측으로만** — holdout 300 고정·acc_shuffled 분리·1변수·±4%p 노이즈 밴드가 CoT·힌트 주입·하드 셔플 같은 그럴듯한 아이디어를 데이터로 기각하게 했다. **보조 모델은 학습 설계에만, 추론은 단일 모델** — Gemma4/CLIP/OWL-ViT 인사이트를 증강 가중치로 LoRA에 내재화하여 규정 적합성과 자원 효율을 동시에 확보했다.

### 6.2 한계점 및 향후 발전 방향

1. **검증셋-리더보드 분포 불일치**: 하드 셔플(holdout +0.4%p / Public −1.1%p)과 v10 힌트(Public 무효 / Private +2.85%p) 등 판정 역전 사례가 반복 관측되었다. 252샘플 holdout의 통계력 한계이며, 층화 추출 기반의 더 큰 검증셋 설계가 필요하다. 재셔플 증강으로 holdout을 크게 끌어올린 exp07(48.41%)이 Private에서 베이스라인보다 낮은 0.740을 기록한 것이 이 불일치의 첫 사례였다.
2. **타깃 증강의 세그먼트 직접 개선 미확인**: sparse_camX ×4 증강은 총점을 올렸으나 해당 세그먼트 자체 정답률은 무반응(20/83 유지). 약점 유형 근본 개선에는 유형 전용 커리큘럼 등 추가 처방이 필요하다.
3. **학습 커버리지 유실**: ×2 증강 dense 계열의 완전미학습 집중 문제. 개선안: ev_4+·dense_camX에 ×3~4 확대, 8유형 멀티티어 증강, Stratified DataLoader 도입(§4.4 처방 참조).
4. **이미지 물리 힌트의 실시간 활용 미완**: 정합률 ~60% 한계로 추론 탑재 기각. 검출 신뢰도 향상 시 씬 분할 탐색 공간 83.3% 축소 논리를 추론에 직접 활용할 여지가 있다.
5. **비전 인코더 적응 미실시**: LoRA를 LLM Attention에만 적용, 비전타워는 동결. 쌍교환 오답의 시각 미세 구분력 개선에는 비전 LoRA가 유망한 후속 과제다(8GB OOM 제약으로 미실시).
6. **4B + 우도 TTA 조합 미제출**: holdout +4.76%p를 실측한 4B에 TTA를 결합하면 VRAM 3.8GB로 최종본에 근접할 가능성이 있으며, §5.2 자원 효율 분석을 완성하는 최우선 후속 실험이다.
